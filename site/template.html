01the measurement

The cliff sits just above the default.

Twelve utterances, streamed in real time at each gate setting. Flat at 1.00 through every value up to and including the 500 ms default, then straight to zero. Moving the gate to 700 ms removes the effect entirely at this hesitation length.

02the line

This is what the recogniser is actually given.

The same utterance down a real telephony path: 8 kHz G.711, call-centre babble, dropped packets. Everything above 3.4 kHz — the detail that separates one digit word from another — is gone before any model sees it.

Degradation is applied to the waveform, not simulated in software the model can detect. Noise is mixed at a measured SNR; the codec round trip goes through ffmpeg, not an approximation.

03where it happens

Four output modes. One keeps the number.

Same audio, same hesitation, same gate. The recogniser hears all seven digits every time — but only verbatim returns them. The romanising modes drop one, and on shorter utterances they drop the number entirely.

04the smoking gun

The partial is complete. The final is not.

Every message on the socket, no early exit. The streaming partials carry the whole utterance. The final that lands 105 ms later has the digits removed — while reporting end_s 3.607, claiming to cover the entire turn.

05read before citing

What this is not.

06the tool

Point it at your own agent.

The harness is the durable artefact; the numbers are just what it found on one afternoon. An adapter is a single method.

uv venv --python 3.12 && uv pip install -e ".[agent]"
python tests/test_asli.py                 # 9 checks. no keys, no network

echo "SARVAM_API_KEY=..." >> .env
uv run asli check                         # one call, raw event stream
uv run asli sweep --suite pir --agent sarvam --pause-ms 700

Implement run(pcm, spec) -> Result, emit timestamped speech_start / speech_end / transcript events, and every metric on this page follows.
